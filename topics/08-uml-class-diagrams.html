Before we start

Why this matters

Your sequence diagrams are full of messages: verifyPIN(), withdraw(), debit(). Which class owns each one, and what does each class need to remember?

The class diagram is the blueprint programmers turn into code and database tables. It is where all the earlier models meet: nouns from the SRS become classes, messages from sequence diagrams become operations.

This topic covers both labs: the basic class diagram (Lab IX) and the extended one with inheritance, abstract classes and interfaces (Lab X).

Concept 1 of 15

UML and the class diagram

UML (Unified Modeling Language) is the standard visual language for the architecture, design and implementation of software. Its diagrams fall into two families:

Structural (static)Behavioural (dynamic)
Class, object, component, deployment, packageuse case, sequence, communication, activity, state machine

A class diagram shows the classes of a system, their attributes and operations, and the relationships between them. It is the most used UML diagram and the only one that maps almost one-to-one onto code.

  • Describes the static view of the system.
  • Models how the elements of that view collaborate.
  • Describes the functions the system performs through its operations.
  • Is the blueprint for object-oriented code (Java, C#, Python) and for the database design.
  • Supports forward engineering (diagram → code) and reverse engineering (code → diagram).

Class diagram basics

Anatomy of a class

  • Name: centred, bold, starts with a capital letter, singular noun (Account, not Accounts).
  • Attributes: left-aligned, first letter lowercase, one per line: visibility name : type = default, e.g. - balance : double = 0.
  • Operations: visibility name(parameter : type) : returnType, e.g. + withdraw(amount : double) : boolean.
  • The attribute and operation compartments are optional; an empty box with only a name is fine in an overview diagram.

Relationships

Association and multiplicity

  • An association is a lasting structural link: objects of one class hold references to objects of the other.
  • Bidirectional (plain line): both classes know each other. Unidirectional (open arrow): only the source knows the target.
  • Label it with a name (a verb: owns) and optionally role names at the ends.
  • Multiplicity at each end says how many objects take part: 1, 0..1, *, 1..*, 2..4.
  • Read multiplicity from the far end: “one Company employs 1..* Employees; each Employee works for 1 Company.”

class House {                       // composition
    private List<Room> rooms = new ArrayList<>();
    House() { rooms.add(new Room("Kitchen")); }   // parts created inside
}
class Department {                  // aggregation
    private List<Teacher> teachers;
    void add(Teacher t) { teachers.add(t); }       // parts come from outside
}
If you delete the House, its Rooms go too (composition). If a Department closes, the Teachers still exist (aggregation). When in doubt, use a plain association — it is never wrong, only less precise.

Concept 8 of 15

Generalization and abstract classes

  • Generalization is inheritance: the child is a kind of the parent and inherits its attributes and operations. Draw a solid line with a hollow triangle pointing to the parent.
  • An abstract class cannot be instantiated; its name is written in italics (or marked {abstract}).
  • An abstract operation has no body; it is also italic, and each concrete subclass must implement it.
  • Draw one triangle and merge the lines when several classes share a parent.
abstract class Person {
    private String name, address;
    abstract void printInfo();
}
class Employee extends Person { ... }

Extended class diagrams

Interfaces and realization

  • An interface is a named set of operations with no implementation — a contract. Show it as a class box with «interface» above the name.
  • Realization (implementation): a dashed line with a hollow triangle from the class to the interface. The class promises to implement every operation.
  • A class can realize many interfaces but (in Java) extend only one class.
  • Example from the manual: an Owner interface with acquire(property) and dispose(property), realized by both Person and Corporation — in very different ways.
interface Payable {
    boolean pay(double amount);
    void refund(String id);
}
class DebitCard implements Payable { ... }

Concept 11 of 15

Example: a telephone

  • A Telephone aggregates a Ringer, a CallerId and an AnsweringMachine (hollow diamonds at Telephone).
  • The AnsweringMachine is composed of its recorded Messages (filled diamond): delete the machine and the messages go with it.
  • A Line connects 0..* telephones; each telephone is on 0..1 line.
  • Every attribute is private (-) with public operations (+).

Concept 13 of 15

How to design a class diagram

  1. Identify the classes. Underline the nouns in the SRS and use case descriptions; keep the ones the system must remember (Account, Card), drop synonyms, attributes (balance) and actors that are outside the system.
  2. Add attributes — facts about each class (name, address, dob).
  3. Add operations — the verbs, and every message from your sequence diagrams.
  4. Find relationships: “has / owns” → association or aggregation/composition; “is a kind of” → generalization; “implements” → realization; “uses briefly” → dependency.
  5. Add multiplicities at both ends of every association.
  6. Review against the use cases: can every scenario be carried out with these classes?

Noun analysis on the ATM description

“A customer inserts a debit card into the ATM. The bank checks the PIN and the balance of the account. Each transaction — a withdrawal or transfer — is recorded with its date.”

Classes: Customer, DebitCard, ATM, Bank, Account, ATMTransaction, Withdrawal, Transfer. Attributes: PIN (of card), balance (of account), date (of transaction).

Worked example 2

A Library has many Books; a Book belongs to one Library. A Book can exist in a donation list before it joins a library. Which relationship and multiplicities?
Show the solution
Aggregation (hollow diamond at Library): the book can exist without the library. Library end 0..1 (a donated book has no library yet), Book end 0..*.

Worked example 3 of 3

Worked example 3

SavingsAccount and CurrentAccount both have accountNo and balance and both implement calculateInterest() differently. Model it.
Show the solution
An abstract class Account with - accountNo : String, - balance : double and the abstract operation + calculateInterest() : double. SavingsAccount and CurrentAccount each generalize to Account (hollow triangle at Account) and implement calculateInterest().

Summary

Summary

  • A class box has name, attributes (visibility name : type) and operations (visibility name(params) : type).
  • Visibility: + public, - private, # protected, ~ package; underline = static, italic = abstract.
  • Association (with multiplicity) < aggregation (◇, independent parts) < composition (◆, parts die with the whole); dependency is a short “uses”.
  • Generalization (hollow triangle to the parent) = inheritance; realization (dashed) = implementing an interface.
  • Find classes from nouns, operations from verbs and sequence-diagram messages.
  • Check the class diagram against the use cases and sequence diagrams.
