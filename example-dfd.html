1 Introduction

1.1 Purpose

These diagrams show where data enters the USMS, which processes transform it, where it is stored and where it leaves. They model the functional requirements of the SRS (section 3.2) and are the starting point for the use case and class models.

5 Level 2: process 2.0 Manage enrollment

No.ProcessWhat it does
2.1List open sectionsShows each open section with code, title, credits, schedule and seats left (FR-02).
2.2Check prerequisitesCompares the course’s prerequisites with the student’s passed courses (FR-03, BR-02).
2.3Check seats, credits, clashesChecks for a free seat, the credit limit and time clashes (FR-08–FR-10, BR-01).
2.4Record or rejectRecords the enrollment if every check passed, otherwise states each reason (FR-12).
2.5Drop courseMarks an enrollment as dropped before the drop deadline (FR-11).

Balancing with 2.0. In: course choice (= browse request + section choice + drop request), sections & seats (= open sections + prerequisites + seats & schedule), passed courses, enrolled courses. Out: courses & status (= course list + enrollment status + drop status), enrollment changes (= new enrollment + dropped enrollment). Every flow of 2.0 on Level 1 is accounted for.

7 Process specifications

7.1 2.2 Check prerequisites (structured English)

FOR EACH prerequisite P of the chosen section’s course
    IF the student has a grade for P
       AND that grade is D or higher          (BR-02)
        mark P as satisfied
    ELSE
        add P to the missing list
IF the missing list is empty
    pass the checked request to 2.3
ELSE
    reject with “<P> must be passed before <course>” for each P

7.2 2.3 and 2.4 Check and record (decision table)

Condition / actionR1R2R3R4R5
Prerequisites satisfied (from 2.2)YNYYY
A seat is freeY–NYY
Credits after ≤ limit (21, or 15 on probation)Y––NY
No time clashY–––N
Record enrollment✓
Reject: missing prerequisite✓
Reject: section full, offer waiting list✓
Reject: credit limit✓
Reject: time clash✓

“–” means the condition is not checked: the first failing check decides the message. A real implementation may collect every failing reason at once; the SRS (FR-03) asks only that each missing prerequisite is named.

7.3 4.0 Handle fee payment (structured English)

amount due = enrolled credits × per-credit fee + semester fee        (FR-18)
send payment request to the gateway
WHEN a payment status arrives
    IF the signature is valid AND status = success
        IF no payment is recorded for this invoice yet
            record the payment, issue a receipt number      (FR-20)
            send the receipt and a payment confirmation
IF no status arrives within 60 seconds OR status = failed
    leave the invoice unpaid and show how to retry         (FR-21)

8 Rule check

  • ✓ Every process has at least one input and one output (no “black holes” or “miracles”).
  • ✓ Data moves between an entity and a store only through a process.
  • ✓ Every store is written by at least one process and read by at least one process.
  • ✓ Every flow is labelled with a noun phrase describing data.
  • ✓ Level 1 balances with Level 0, and Level 2 balances with process 2.0.
  • ✓ Processes are numbered 1.0–5.0 and their children 2.1–2.5; stores D1–D5 keep their numbers on every level.
